# 데일리체크 (DailyCheck)

구글 시트에 점검사항을 적어 두면 → 휴대폰 앱이 그 항목으로 입력 화면을 만들고 → 현장에서 입력하면 시트의 그날 날짜 열에 자동으로 기록됩니다. 시트에 쌓인 값으로 항목별 주간·월간 보고서를 보여 줍니다.

기획서: [기획서.md](기획서.md)

```
  점검사항      기준        11/24   11/25            휴대폰 화면
  밸브          on/off      on      on       →   [밸브]            [on][off]
  오일 (ml)     100~150     120     165      →   [오일]   (ml)     [ 165 ] 📷   ← 기준 벗어남: 빨간색
  온도 (℃)      95 이하, 사진 85      86       →   [온도]   (℃)      [  86 ] 📷
  점검자                    박현장  김점검    ← 앱이 자동으로 채움
```

## 실행

```bash
npm install
npm run dev        # 앱 (같은 와이파이의 휴대폰에서 http://<PC IP>:5173)
npm run mock       # 개발용 가짜 시트 (앱에서 주소 http://localhost:8787, 비밀번호 1234, 승인 비밀번호 0000)
                   #   승인 비밀번호 없이 시험:  ADMIN_PIN= npm run mock
npm run build      # 배포용 빌드 → dist/
```

## 진짜 구글 시트 연결

[apps-script/설치방법.md](apps-script/설치방법.md) — 시트에 스크립트 붙여 넣기 → 웹 앱 배포 → 주소를 앱에 입력 (10분)

## 기능

- **시트 → 입력 화면**: 시트 한 행 = 화면 한 줄 `[항목] (단위) [값] 📷`. B열 «기준»으로 입력 방식·이상 판정 결정, 기준 열이 없어도 단위·기존 값으로 추측
- **입력 → 시트 자동 기록**: 그날 날짜 열이 없으면 날짜 순서에 맞게 자동 추가, 점검자·점검시각 행 자동 기록, 동시 입력 잠금
- **사진**: «사진» 기준 항목과 기준을 벗어난 항목에 📷 버튼. 날짜·시간·점검표·항목 이름 워터마크. 드라이브 폴더에 저장되고 시트 칸에 링크 메모
- **변경 확인(승인)**: 시트의 점검항목을 고치면 앱 홈에 «변경 확인»이 뜨고, 추가·삭제·이름 변경·기준 변경을 보고 승인해야 모든 폰에 반영 (승인 비밀번호는 선택 — 1인 사업자는 버튼만). 확정본은 시트의 숨김 탭 `_승인본`
- **기록 잠금과 정정**: 저장 전 확인 화면 → 저장하면 값이 잠김(오늘 것 포함) → 고치려면 «정정»(사유 필수, 승인 비밀번호 선택). 원본·정정값·사유·시각은 시트의 숨김 탭 `_기록`(덧붙이기만)·`_정정`에 남고, 시트는 이미 기록된 칸을 덮어쓰지 않음. 기록 삭제 기능은 없음
- **기록 검사·시트 보호**: 장부(`_기록`)와 시트를 비교해 시트에서 직접 바뀐 값·지워진 행/열을 찾고, 되돌리거나 사유를 남겨 인정 (6시간마다 자동 검사). 기록 칸은 구글 시트의 «보호된 범위(경고)», 장부 탭은 주인만 수정 가능으로 자동 설정
- **오프라인**: 인터넷이 없으면 휴대폰에 보관 → 연결되면 자동 전송 (앱 시작·화면 복귀·인터넷 복구 시)
- **보고서**: 주간/월간 전환, 요약 문장, 점검 달력, 항목별 합계·평균·최소·최대·추이 그래프·날짜별 값, 이상 목록, 인쇄/PDF, CSV
- 시트 없이 앱 안에서 점검표를 만들어 쓰는 방식도 남겨 둠 (HACCP 등 서식 템플릿)

## 구조

- `apps-script/Code.gs` — 구글 시트에 붙이는 연결 스크립트 (읽기·쓰기·사진 저장)
- `mock/sheet-server.mjs` — Code.gs 의 함수를 그대로 써서 만든 가짜 시트 서버 (개발·테스트용)
- `src/sheet/parse.ts` — 시트 행 → 입력 항목 해석 (단위, 기준, 선택지)
- `src/sheet/changes.ts` — 시트와 확정본 비교 (추가·삭제·이름·기준 변경)
- `src/sheet/integrity.ts` · `src/pages/Integrity.tsx` — 기록 검사 (비교는 시트 스크립트의 `dc_verify`)
- `src/correct.ts` — 정정 (시트 점검표는 시트 스크립트로, 앱 점검표는 기록에 정정 내역 저장)
- `src/pages/Changes.tsx` — 변경 확인·승인 화면
- `src/sheet/sync.ts` — 연결 설정, 보내기·받기, 자동 동기화
- `src/pages/Inspect.tsx` — 한 줄 입력 화면, 사진 버튼
- `src/pages/Report.tsx` — 주간·월간 보고서
- `src/db.ts` — 휴대폰 내 저장소 (IndexedDB)

## 아직 안 된 것

- 휴대폰 카메라·홈 화면 설치 실기기 확인 (배포 주소: https://dailycheck-eta.vercel.app)
- 설치 단순화: «사본 만들기» 템플릿 시트
- 월간 보고서를 시트 탭 + 차트로 자동 생성 → 구글 슬라이드 연동

저장소 방향: 점검 데이터의 본체는 고객의 구글 시트·드라이브입니다. 별도 DB는 두지 않습니다 (이유는 [기획서.md](기획서.md) 3장).
